## 표본과 대조의 의미

지도 크기는 모두 **250×250 = 62,500칸**이다. 세계 지형 seed는 `blackjack`이며, 지도 seed A/B는 각각 `MoreMushrooms-Field-A-20261011`, `MoreMushrooms-Field-B-20261011`이다. 시작 게임 틱은 1, 절대 틱은 320001이다.

6개 지원 바이옴에서 현재 설정 12지도와 v0.5 가중치 대조 12지도를 생성했다. 비지원 Tundra에서는 현재/대조 각각 2지도를 생성했다. 장기 채집 조건용 6지도를 추가로 재생성해 총 34회다. 채집용 지도는 대응하는 무채집 지도와 최초 식물·지형/지붕·눈의 SHA 및 46종 개체 수가 모두 일치했다.

바이옴별로 자연 세계에 존재하는 땅 타일 중 기존 MapParent가 없는 곳을 선택했다. mutator가 없는 곳, 평지, 작은 tile ID 순으로 결정했으며 생성된 버섯 수를 보고 타일을 골라 바꾸지 않았다. 같은 바이옴의 A/B와 대조·채집 복사본은 같은 타일을 사용한다. **바이옴당 지리 타일은 하나, 지도 seed는 둘**이므로 이 표본으로 바이옴 전체의 평균·확률을 추정하지 않는다.

수확 원물을 가진 야생 버섯 plant definition 46종을 집계했다. 재배용 `RMush_PlantEnoki`와 모둠 선택용 식물은 제외하고, 야생 팽이 `RMush_PlantEnokiWild`는 기존 Enoki에 대응시켰다. `기존15`는 최초 식용10종과 이후 독성5종, `추가31`은 그다음 추가분이다. 46종 모두 각 census에 0개 항목까지 포함된다.

**v0.5 대조는 현재 실행환경에서 wildBiomes 가중치만 옛 값으로 교체한 proxy다.** 현재의 46종 정의, 제철·생성 장소 제한, 개체 상한, Harmony 패치는 계속 적용된다. 구버전 DLL 실행이나 구버전 전체 게임플레이 비교가 아니다. 대조 지도 생성이 끝나면 원래 definition 목록 참조와 바이옴 캐시를 복구했다.

## 2. 120일 통제 생태 모형의 조건

온대림·아한대림·열대우림에서 각 2seed를 무채집/채집으로 나눴다. 게임 전체를 120일 정상 실행한 시험이 아니다. 일시정지된 게임에서 시계를 전진시키며 **버섯의 native `Plant.TickLong`을 2,000틱마다**, 모드 생태 component를 **2,500틱마다** 시간 순서대로 호출했다. 같은 시각에는 식물 갱신→생태 갱신→일일 채집 순서다. 각 series는 7,200,000틱, 생태 호출2,880회, 일별 기록0~120일의121개를 가진다.

빛은 native 천체/sky 갱신을 사용했다. 기온은 native tile temperature cache를 갱신하고 절대 틱의 native 계산값+지도 기온 offset과 대조한 뒤 야외 room 온도를 native 방식으로 동기화했다. 초기 날씨는 고정했다. 장기 관찰 대상의 초기 날씨는 모두 Clear였다.

초기 눈은 지우지 않았다. native `SteadyEnvironmentEffects`의 융설 함수, 1틱당 칸 방문 수, `cellsInRandomOrder` 순환, `SnowGrid.AddDepth`를 사용해 **눈 처리만 재구성**했다. 기온은 native 60틱 cache 간격에 맞춰 평가했다. 눈이 없거나 녹지 않는 구간에서도 방문 순서와 경과 틱을 보존했다. 전체 steady environment tick을 실행한 것은 아니며 새 강설이 없는 조건을 요구했다. **최종 12개 장기 표본은 처음부터 눈0이어서 양의 눈이 실제로 녹는 경로는 이 실행에서 관측하지 못했다.**

다른 식물은 초기 상태를 유지했다. native 기본 야생 식물 재파종, 동물, 날씨 전환, 사건, 실제 폰 작업·이동·도달성·저장·섭취는 생략했다. 지형·식물 제거, 강제 성숙, 강제 군락 생성, 재생 확률 우회는 하지 않았다. 최초 census 후에만 대응 무채집/채집 지도에 동일한 생태 RNG seed를 설정했고, 이후 조건부 난수 소모는 채집 여부에 따라 달라질 수 있다.

채집 조건은 하루에 한 번, **그 시점에 성숙·수확 가능·원물 산출 가능한 각 개체를 독립확률25%로 선택**했다. 전체의 정확히25%를 고정 개수로 뽑은 것이 아니다. 지도에 배치하지 않은 Plants10 native colonist의 실제 수확 능력치와 native 작업의 성공/산출 공식을 적용하고 `PlantCollected`를 호출했다. 성공 시 수확 알림을 명시적으로 연결했으며 폰이 실제 작업을 수행하거나 원물 스택을 운반한 것은 아니다.

기온 범위는 하루 한 번 같은 게임 시각의 기록 최저/최고이며 연속 시간의 극값이 아니다. 고리 기회 검사는 cooldown·예산·상한 사전 조건을 지난 생태 호출 수이며, 확률 추첨 성공이나 위치 조건 통과 횟수가 아니다. 빈칸/완전한 고리 조건별 탈락 횟수는 계측하지 않았으므로 이를 성공 부재의 유일한 원인으로 단정하지 않는다.

**아한대림의 0은 아한대림 전체의 장기 공급0을 뜻하지 않는다.** 선택한 타일은 최초−2.84°C로 현재 모드의 생성 온도 조건 밖이었다. 최초 snowBlockedFertileCells와 장기 초기 눈은0이었으며, 첫 계절의 native commonality가 양수인 버섯20종은 제철 계수도 모두 양수였다. 따라서 초기0을 제철 계수0이나 눈 때문이라고 설명하지 않는다. 이후 여름에는21.41°C까지 올랐지만, 현재 고리 허용4종(Button/PurpleBlewit/GiantPuffball/ShaggyInkcap)은 이 바이옴의 native commonality가 모두0이다. 기본 자연 재파종을 생략한 모형에서 초기 개체도 채집 대기표도0이므로 새 공급원이 없는 상태가 유지됐다. 열대우림의 초기 개체 소진도 기본 재파종을 생략한 결과와 분리해서 해석해야 한다.

## 5. 검증 범위와 해석

- 최초 census34개 모두46종 항목을 포함했고 장기12조건 모두121개 일별 기록을 남겼다. 일별 종별 CSV는66,792행, 이벤트 CSV는3,112행이다.
- 대응하는 무채집/채집 6쌍은 최초 식물·지형/지붕·눈의 SHA와 종별 개체 수가 일치했다.
- 각 조건의 `최초 + 고리 추가 + 재생 추가 − 자연손실 − 채집 시도 = 최종` 및 `예약 − 실제 재생 − 만료/무효 = 남은 대기표`가 모두 맞았다.
- 이벤트의 수확량 합계, 종별 수확량 합계, series 원물 합계, Nutrition 분리 합계가 일치했다. 고리·재생 이벤트 수와 실제 생성 counters도 대조했다.
- native 생태 호출 합계34,560회, 개별 식물 native TickLong 합계988,512회, native 기온 cache 대조77,760회였다. 기온 cache 최대 오차는 모든 조건에서0이었다.
- 각 조건은 눈 모형 경과7,200,000틱, native 방식의 1틱당38칸, 실행/생략 방문 합계273,600,000회를 보존했다. 표본에 초기 눈이 없어 융설량은0이었다.
- 사용자 저장이나 설정을 변경하지 않는 별도 savedata 프로필에서 실행했다. Core 단독 결과이며 사용자 모드 조합의 생태·성능 호환성을 입증하지 않는다.

앞선 QA 시행의 definition 수/JSON 직렬화 문제는 하네스에서 수정했다. `20261011-003315-840-FieldEcology-Core`는 기온 cache가 고정되는 모형 결함 때문에 장기 결과를 폐기했다. 그 실행의 초기 census와 장기 수치를 최종 표에 섞지 않았으며, 이 문서의 모든 수치는 온도·눈 시간 처리를 적용한 `004823-717` 최종 실행에서 가져왔다. 최종 native 오류0과 이러한 이전 하네스 문제는 구분한다.

이 자료는 현 설정의 지도별 실제 구성, 추가 생태 기능의 관측 결과, 예산·대기표 보존을 평가하는 자료다. 기본 자연 재파종·동물·날씨·이동 노동을 포함한 실게임 공급량을 주장하지 않는다. 후속 검토가 필요하다면 지리 타일/시드 표본 확대, 아한대림의 따뜻한 생성 시점 및 native 기본 재파종 포함 대조, 실제 초기 눈이 있는 계절 전환 관찰을 별도 설계해야 한다. 이번 관측만으로 생산 밸런스는 바꾸지 않았다.
